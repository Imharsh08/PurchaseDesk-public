FMS tracker

Every indent through ST1–ST9 against each step's TAT, Sundays skipped, urgent TAT separate. Overdue cells turn red and the next doer gets an email.

Daily or weekly counts in packs and loose qty, minimum and re-order levels, what's already on order, and a suggested order rounded to whole packs.

Spend by vendor, item or month, savings, price variance, vendor scorecards, PO and GRN registers and the doer scorecard, each one export away.

How it flows

Who does each step, what the app does on its own, and how the pieces are hosted.

Lanes are roles; columns are the FMS steps. Yellow boxes are decisions; dashed boxes in the bottom lane are what PurchaseDesk works out by itself. Scroll sideways on a small screen.

The browser app is static files on Cloudflare Pages. Everything that touches data or secrets runs in one API next to the database, inside a single Neon project. Google and Gemini are optional.

Run it for
your plant

Free plans on Neon and Cloudflare cover a typical purchase team. No Google account needed: admins create users with email and password.

  1. STEP 1 · NEON

    Database and first admin

    Create a Neon project, link it, create the tables and your admin login.

    neon link
npm run db:deploy
npm run db:seed
  2. STEP 2 · NEON FUNCTION

    Deploy the API

    One command deploys the API next to the database; set your Pages address and a session secret once.

    npm run api:build
neon functions deploy api \
  --env WEB_APP_URL=https://you.pages.dev
  3. STEP 3 · CLOUDFLARE PAGES

    Connect the repo

    Build command npm run web:build, output web/dist, and VITE_API_URL set to the API address. Every push redeploys.
